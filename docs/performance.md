# 性能策略与验证

## 已采用的路径

- 桌面界面继续由 WebView2 承载。活动终端使用 xterm WebGL2；每个 WebView 最多保留 2 个 GPU 渲染器，后台保温 5 秒，快速切换复用上下文，超时或达到配额时释放。后台继续解析输出并保留终端缓冲区。
- 文件表格采用虚拟列表，保留目录/文件动态表头、选择、排序、菜单与列宽调整；文件名自然排序复用 Intl.Collator。
- 传输完成覆盖检查和源文件检查后先登记 Queued 并返回。后台按原有 4 个槽位调度，排队期间可取消、暂停、恢复。每个 SFTP 实例最多接受 128 个未结束任务，超过时明确报错。
- 配置文件读取、KDF 与解密通过阻塞工作线程初始化，并发启动请求共用一次初始化结果。窗口先展示启动状态，配置就绪后开放操作。没有降低密码学参数。
- 设置、备份、隧道、传输中心在首次打开时加载，并保持已打开面板的本地状态；相关样式随功能加载。编辑器和日志窗口不会执行主窗口 App 模块。
- 主窗口在轻量外壳提交后立即显示，不依赖隐藏 WebView 的动画帧或事件订阅。配置读取仍遵守先订阅后快照的顺序；显示握手去重，避免重复 effect 或页面重载把托盘窗口拉到前台。
- 构建按实际依赖拆包，终端/文件工作区首次使用时才加载。首屏外壳静态 JS 约 200 KB，初始工作区静态 JS 总计约 685 KB；检查脚本 `node tools/check-startup-bundle.mjs` 验证大小预算与延迟模块边界。
- Windows 系统版本通过 `RtlGetVersion` 原生查询并缓存，不再在 UI 线程同步运行 `cmd /C ver`。应用信息查询在阻塞工作线程执行，避免启动元数据阻塞原生事件循环。
- 终端使用每终端独立的 Tauri 原生 Channel/Raw 响应。原生合并缓冲从分配时预留一个帧头字节，完成后直接移交 IPC，省去重新组帧复制；帧头包含类型与裸 CR 扫描提示，正文保持原始内容。前端通过 Uint8Array 视图交给 xterm；stdout、stderr、退出提示、关闭通知在同一通道排序。输出热路径不生成 UUID、本地化时间或 Base64 文本。
- 命令输入框通过 xterm 的公开 input API 发送，启用下一批回显立即解析的路径。交互后的首批输出和空闲后的首包立即发送；持续输出仍按 8 ms / 64 KiB 合并。
- 每终端最多允许 1 MiB 尚未消费的输出，xterm 完成解析后累计确认；未挂载的终端由回放缓冲接管，组件销毁时释放尚未确认的消费额度。确认按 64 KiB / 8 ms 合并；这不是带宽限速。关闭会唤醒受流控阻塞的发送任务。
- 目录标记使用 xterm OSC 解析器，普通提示符与交互判断共用末尾最多 8 行 / 8192 字符，前台最多读取 20 次/秒、后台 5 次/秒。原生裸 CR 扫描按 CPU 自动选择 AVX2、SSE2、NEON 或通用实现，前端不再逐块重复此扫描；完整 UTF-8/VT 解析仍由 xterm 负责。
- 终端回放缓冲按单终端 4 MiB / 4096 条、每个 WebView 总计 16 MiB / 32 份缓存限制并摊销回收。按底层 ArrayBuffer 实际大小计量，同一缓存内的共享视图只计一次。正常输出不额外请求整屏刷新；该限制不代表 IPC 传输带宽或 xterm 全部内存。具体实测与复现见 [terminal-performance.md](terminal-performance.md)。

## AI API 路径

- 安装后启动遇到 Windows 10048 / `AddrInUse` 时，先在 10 秒内按 100 ms、200 ms、400 ms、最多 500 ms 的间隔重试原端口；仍未恢复时延长 5 秒，总计最多 15 秒。每次重新读取当前授权设置，退避期间释放生命周期锁；停止服务、显式启动/重置密钥、配置替换或退出会取消本次自动恢复。其他错误不重试，也不更换端口或强制结束占用进程。
- 停止/退出先通知 HTTP 服务关闭监听，再等待生命周期操作。后台任务取消、HTTP 请求收尾及日志落盘并行等待；正常停止时由句柄统一执行一次 SSH 清理，服务异常退出仍保留应急清理。
- 状态查询和事件统一携带 `starting` / `error`，主窗口及 AI API 面板显示正在启动、运行、停止或启动失败。失败原因保留到手动处理；在途旧查询不能覆盖新运行事件。回归使用临时本机监听端口模拟占用、释放与取消，未执行安装器覆盖当前安装版。
- SSH 执行就绪检查不再无条件扫描 SFTP 实例；会话存在性检查不复制整个会话配置和私钥字段。
- 任务事件在历史缓冲与 SSE 订阅者之间共享 Arc，SSE JSON 文本按事件缓存一次，避免每个订阅者深复制/序列化大段输出。
- SSE 订阅、任务取消的鉴权只读取会话标识，不复制最多两份 1 MiB 输出快照。历史与实时事件用序号衔接，过滤重复，广播与状态提交保持同序。
- 原有 Bearer 鉴权、会话授权、危险命令检查、全局/会话并发上限、SSH 连接复用及超时取消保留。字段库/OpenAPI 原本已有缓存和 ETag；执行请求不依赖先读取字段库。
- 操作日志中的 `output` / `stdout` / `stderr` 提供文本视图，JSON 转义只解析一次，换行按实际文本展示；JSON 视图和整条日志复制保留原始字段与转义，文本复制只复制所选输出。

## 工作区与更新格式迁移

- 工作区新格式为 RPVAULT v2 二进制容器，直接保存 16 字节盐、24 字节 nonce 和密文。继续使用 Argon2id + XChaCha20-Poly1305，文件头作为 AAD 一并认证；解析时校验版本、长度及 KDF 参数上界。
- 已完成迁移后，工作区和备份导入仅接受二进制 v2；移除 JSON/Base64 v1 解码、旧 KDF 字符串解析和自动格式迁移分支。旧格式明确报错，不进入密码迁移界面，也不覆盖原文件。既有迁移备份不再参与运行。
- 更新仅下载 `latest.json.sig.bin` 原始 RSA-PSS/SHA-256 签名；404、签名错误和服务器故障均不回退旧 `.sig`。发布流程也停止生成旧 `.sig`，仅支持二进制签名客户端的自动更新。安装器启动不再使用 PowerShell EncodedCommand。
- 应用源码和发布流程不再使用 Base64，移除直接依赖；SSH 等第三方协议库的传递依赖和测试服务器标准指纹编码仍按协议使用。二进制格式减少编码开销，不改变既有密码学算法。

## 诊断入口

主窗口 DevTools 控制台：

```js
window.__HELM_PERFORMANCE__.reset()
// 执行要测量的操作后：
console.table(window.__HELM_PERFORMANCE__.snapshot())
```

每类操作通过固定 TypedArray 环形缓冲保留最近 128 个样本，总计最多 128 类；仅查询快照时排序。记录命令名、耗时与成功/失败，不保存请求参数、返回内容、路径或凭据。IPC 耗时包含后端实际工作及通信，重试等待不计入单次尝试；P95 是当前样本分位数，不是生产用户统计。`startup:config-ready` 从前端开始加载配置计时，不能当作进程冷启动耗时。

`terminal:parse` 是前端提交到解析回调的耗时，包含排队，不是纯 CPU 时间；`terminal:input-to-next-output` 是输入至下一批输出解析完成，不是命令执行完成，也不能在持续日志下直接当作命令回显 RTT。

Rust 日志中的 `Startup vault ready: duration_ms=...` 用于定位配置初始化。已有 SSH 日志继续提供 TCP、握手、认证和 PTY 分段耗时。

`Startup phase` 的 `process_ms` 从 Rust 入口开始计时，`navigation_ms` 从主页面导航开始计时。外壳提交、App 提交、监听就绪和工作区就绪分别记录；两种时钟起点不同，不能直接相减当作 IPC 耗时。`Startup main visible` 表示原生完成 show，`Startup app info ready` 记录应用元数据查询耗时；工作区就绪表示配置提交完成，不表示 SSH 已连接或所有延迟面板已加载。

## 本次验证与边界

本机独立 Chrome/Vite 开发环境、相同 FileManager 组件和模拟数据：

| 场景 | 修改前 | 虚拟列表后 |
| --- | --- | --- |
| 1 万条目录的渲染行数 | 10000 | 约 14–15 |
| 页面 DOM 节点数 | 210255 | 约 492–513 |
| 等待双 animation frame 的一次渲染测量 | 约 29.6 秒 | 约 1.1–2.0 秒 |
| 构建后的首屏公共 CSS | 318898 字节 | 约 106 KB |

这些结果证明大目录 DOM 规模与首屏样式负担下降，不能替代安装版冷启动、真实网络吞吐或用户操作 P95。浏览器手动复验覆盖目录/文件单选、多选表头、滚动到底、右键菜单，以及终端中文按两字节分块、后台输出和 WebGL 切换恢复。

自动检查使用 `npm test`、`npm run build`、`cargo test --manifest-path src-tauri/Cargo.toml --lib --locked`。新增回归覆盖队列无空位取消、暂停恢复的槽位约束、并发配置初始化、终端分块字节顺序、中文流式解码和二进制回放上限。

后续终端隔离验证复用实际 TerminalPanel，模拟 5 ms 服务器回显，覆盖单次发送、回车清空和焦点、中文两字节分块、OSC 目录标记、后台 WebGL 释放及恢复。一次 640016 字节模拟输出在约 80 ms 内完成消费确认，全部字节收到；不包含原生 IPC、SSH 和最终绘制，不能当作安装版吞吐。

Rust 回归覆盖原生 Raw 帧、流控阻塞/释放、重复和乱序确认、SSE 共享缓冲及事件顺序、工作区 v2 备份/篡改拒绝/不支持格式拒绝、二进制签名验证。未执行真实服务器压力测试、安装器替换或安装版 WebView2 全链路复验。启动分段调查见 [startup-investigation.md](startup-investigation.md)。

启动修复后的实际 Release 以隔离空工作区测量五次：启动页停留 137–270 ms，页面导航至工作区提交 511–632 ms，Rust 入口至工作区就绪 872–3838 ms。已消除系统信息同步查询期间约 5 秒的窗口无响应；系统信息查询均不足 1 ms。仍有两个主页面加载前的较慢样本（含一次复用缓存），不承诺全部启动在一秒内，也不把五个样本解释为 P95。完整分段和测量边界见上述调查记录。

## 后续基准

1. 使用同一 Release 构建、同一机器和数据，分别记录冷启动/热启动、进程启动至窗口可见及首次可操作；至少重复 20 次，报告中位数和 P95。
2. 使用 1 千/1 万/5 万条目录验证滚动、搜索、排序、选择和内存，并检查网络目录列表返回与前端渲染各自占比。
3. 使用 1/5/20 个终端及持续日志输出测量 CPU、显存、渲染帧耗时与积压。WebGL 回退不得丢失字节、全屏程序状态或中文。
4. 项目已有 `tools/test-sftp-performance.ps1` 本地延迟模拟脚本。当前脚本调用 debug cargo test，结果仅用于同配置回归；正式吞吐应以 Release 构建、真实目标磁盘和代表性 RTT 验证，同时记录 CPU、磁盘、MB/s 与错误率。

保留现有加密/哈希库的 CPU 自动特性检测，不全局启用 AVX2 或 target-cpu=native。终端新增的局部控制字符扫描采用运行时指令集分派，保留 x86、x64、ARM64 与通用路径；真实 RTT 和安装版端到端延迟仍需独立测量。

WebView2 的 JS 解析和编译由 V8 管理，使用其内建 CPU 特性选择。Rust 编译开关不控制 V8；本次前端优化通过减少首屏代码量和等待链生效，没有强制启用 AVX2。
