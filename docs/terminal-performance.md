# 终端性能与输入着色

2026-11-04，在 `a730d63` 基线之上优化终端封装层。主要收益来自移除每块输出的 UUID/本地化时间生成、重复读屏和组帧复制，并复用 WebGL2 上下文。完整 xterm VT/UTF-8 解析器保留，不直接裁剪 `node_modules`。

## 数据路径

`SSH 原始字节 → 自带帧头的合并缓冲 → 原生扫描提示 → Tauri Raw Channel → Uint8Array 视图 → 有界回放 → xterm.write → WebGL2/DOM`

- 合并完成的 `Vec<u8>` 所有权直接交给 IPC，不再复制完整正文重新组帧。回归测试检查 Raw 回调收到的缓冲指针保持一致。合并期间 Vec 扩容仍可能搬移数据。
- 前端解帧、二进制历史增量和回放复用底层 ArrayBuffer；流式输出通过单调编号标识，无需 UUID 或时间格式化。
- 这只减少应用层复制。SSH 解密、跨进程 IPC、xterm UTF-8 解码/单元格缓冲和 GPU 上传仍有各自的处理与存储，不能称为全链路零拷贝。
- 帧头低两位为 stdout/stderr/system/closed 类型；`0x80` 表示含扫描提示，`0x04` 表示正文含裸 CR。关闭帧仍为单字节 `[3]`，前端兼容旧 `0..3` 帧头，正文不变。帧最大 64 KiB + 1 字节。
- 首批交互回显、空闲后首包立即发送；持续输出仍按 8 ms / 64 KiB 合并，每终端最多 1 MiB 未消费字节，解析后累计确认，保留顺序与背压。
- 普通提示符和交互判断共用最多 8 行 / 8192 字符的屏幕快照，前台最多 20 Hz、后台 5 Hz；显式 OSC 目录标记立即处理。

## CPU 与 GPU

原生裸 CR/CRLF 扫描使用 `memchr` 快速排除无 CR 数据；较长数据按 CPU 运行时检测选择 AVX2（32 字节）、SSE2/ARM64 NEON（16 字节）或通用实现。短回显避免额外分派。测试覆盖未对齐地址、向量边界、末尾 CR 和密集 CRLF，不启用全局 `target-cpu=native`。

SIMD 加速的是控制字符预判，用于滚动策略，不是重写整个转义序列状态机。跨帧 UTF-8、ANSI、OSC、宽字符和备用屏幕仍使用 xterm 6 的流式解析。帧尾 CR 保守视为裸 CR，仅影响滚动提示，不修改字符。

WebGL2 继续使用官方 addon。每个 WebView 最多 2 个渲染器（含加载中），隐藏后保温 5 秒，配额不足时先释放后台渲染器。快速切换复用字体纹理和上下文；禁用、卸载或持续上下文丢失后回退 DOM，输出继续解析。官方 addon 允许约 3 秒的上下文恢复窗口，之后通知回退；再次切换终端或关闭再开启 GPU 可重新加载。

## 颜色与资源管理

用户输入框和已确认的终端回显使用蓝色 `#1d4ed8`；服务器输出保留默认深色与原有 ANSI 配色。使用 xterm decoration，不向 SSH 流插入颜色控制码，也不自行回显输入。密码关闭回显时不会显示或标色。

常见的 `user@host:~$`、`root@host:/path#` 和 `[user@host path]$` 提示符在没有服务端配色时使用绿色 `#047857`，只补色默认前景/背景的可见单元格，保留已有 ANSI 样式。提示符识别复用上述有界读屏与节流，支持宽字符和折行；命令、普通输出及密码提示不属于提示符范围。提示符最多保留 128 段装饰，清屏、重置、备用屏幕、改写或列宽变化时清理对应装饰。

SSH PTY 输出本身没有“这段属于用户”的标签，因此着色采用屏幕精确匹配：仅普通终端中的直接输入及服务端相同回显被标记，支持分块中文、宽字符、折行和简单退格。历史键、光标编辑、补全、复杂多行粘贴及 TUI 等无法可靠映射的场景保守取消着色，继续显示服务器原样内容；不保证任意服务端输出都能做来源分类。清屏、重置、备用屏幕或服务器改写相应屏幕文本时释放对应标记。标色不写入终端回放缓存。

| 资源 | 上限/回收方式 |
| --- | --- |
| 原生未确认输出 | 每终端 1 MiB，解析消费后返还额度 |
| 回放历史 | 每终端 4 MiB / 4096 条；每个 WebView 16 MiB / 32 份，淘汰最久未写入缓存 |
| 回放字节计量 | 计完整底层 ArrayBuffer，同一缓存内共享视图引用计数；最后引用移除时扣除 |
| 异常大缓冲视图 | 底层超单终端预算时不缓存，仍直接交付当前终端并确认消费 |
| 待匹配输入 | 每条最多 4096 字符、最多 8 条、5 秒有效期；定时回收 |
| 输入着色历史 | 最多 128 行装饰，匹配后释放待确认输入字符串 |
| GPU 渲染器 | 每个 WebView 最多 2 个，后台保温 5 秒 |
| 性能诊断 | 最多 128 类，各 128 个 TypedArray 环形样本 |

这些预算限制新增缓存、装饰与并发上下文，不能解释为整个进程或显存仅占 16 MiB。xterm 滚动历史仍遵守设置中的 `scrollback`；达到回放预算后，重建终端只能重放保留的历史尾部，当前已挂载终端的实时数据不因此丢失。

## 本机实测

Windows、Chrome 156、16 个逻辑处理器、GTX 750 Ti / ANGLE D3D11，真实 `TerminalPanel` 本地隔离页面，使用同步模拟回显，无 SSH。预热后每种场景执行三次；前后使用同一组件尺寸、数据和分块。生产构建与 Rust 测试结束后单独测量最终混合场景，避免并发编译干扰。

| 场景 | 优化前 | 优化后 |
| --- | --- | --- |
| 2 MiB 中文/ANSI，1 KiB 分块，全部解析完成 | 155.3–173.9 ms；中位 166.3 ms | 56.8–69.5 ms；中位 69.5 ms |
| 上述场景累计同步提交耗时 | 85.1–92.5 ms | 1.3–1.9 ms |
| 上述场景吞吐 | 11.5–12.9 MiB/s | 28.8–35.2 MiB/s |
| 8 MiB ASCII，64 KiB 分块，阶段性测量 | 180.6–183.1 ms | 173.4–182.0 ms，基本持平 |
| 同步模拟回显 100 次，阶段性测量 | P50 0.1 ms / P95 0.2 ms | P50 0.1 ms / P95 0.2 ms，未观察到改善 |

主要小块场景中位耗时降低约 58%。不同场景收益不同，不能推广为全部终端操作快数倍。解析完成计时含 JS 提交/排队，不含真实 SSH、原生 IPC 和最终像素呈现；`twoFramesMs` 只额外等待两次 animation frame，也不等同 GPU 完成。回显测量由程序主动输入后同步模拟服务端返回，不能解释为物理键盘延迟。单次极值波动明显，不据此宣称低尾延迟。

浏览器基准用同一预生成缓冲的子视图隔离提交路径，两版采用相同方式。2 MiB 场景按引用计数进入回放；8 MiB 场景的底层缓冲超过单终端预算，最终实现只直接交付，不缓存。实际 IPC 每帧拥有独立缓冲，因此浏览器结果不能替代实际多终端堆内存测量。

原生 release 基准在本机检测到 AVX2，预热后各执行 5000 次，以下为每个 **64 KiB** 数据块的平均微秒数：

| 数据 | 标量控制字符扫描 | 自动分派扫描 | 两次复制参考 | 一次组帧复制 |
| --- | --- | --- | --- | --- |
| 无 CR ASCII | 23.125 µs | 0.601 µs | 33.328 µs | 2.097 µs |
| 中文/ANSI/CRLF | 23.147 µs | 1.834 µs | 3.828 µs | 1.783 µs |

复制时间包含分配/释放，Windows 分配器影响明显，不代表稳定倍数。微秒级仅适用于此局部扫描/组帧操作；网络 RTT、远端执行、调度和显示器帧率决定端到端响应，无法承诺整体微秒级输出。

## 复现与验证

在仓库根目录启动独立测试页（避免 `npm run dev` 的端口清理前置动作）：

```powershell
node node_modules/vite/bin/vite.js --host 127.0.0.1 --port 14631 --strictPort
```

打开 `http://127.0.0.1:14631/tools/terminal-benchmark.html`，在 DevTools 控制台执行：

```js
const b = window.__HELM_TERMINAL_BENCH__;
await b.bulk(1024 * 1024, 1024, true); // 预热
const runs = [];
for (let i = 0; i < 3; i++) runs.push(await b.bulk(2 * 1024 * 1024, 1024, true));
console.table(runs);
await b.input(100);
await b.gpu(false);
await b.output("\r\n回退后中文输出\r\n");
await b.gpu(true);
```

原生局部基准与自动检查：

```powershell
cargo run --release --manifest-path tools/terminal-native-bench/Cargo.toml --locked --offline
npm run build
cargo test --manifest-path src-tauri/Cargo.toml --locked --lib
```

以下为当时的验证记录，前端测试源码及运行入口现已移除：前端 130 项通过，后端 221 项通过、2 项需要 Paramiko 环境的既有 SFTP 测试跳过；生产构建通过。回归覆盖原始字节与元数据、SIMD 边界、超长 SSH 消息拆帧保序、IPC 所有权移交、累计消费确认、全局/共享缓冲计量、着色不泄露隐藏密码/不覆盖服务器 ANSI、服务器改写和退格、GPU 配额/超时/迟到加载、诊断环形覆盖。

实际 Chrome 验证了用户输入蓝色与服务器红绿 ANSI、快速标签切换复用同一 canvas、禁用 GPU 后持续输出及恢复，并通过 `WEBGL_lose_context` 注入真实上下文丢失，约 3.25 秒后确认回退和中文输出正常。原生扫描模块通过 i686 和 aarch64 Windows 目标编译检查；ARM64 SIMD 没有在实机执行。本轮未连接真实 SSH 压测，也未执行安装版 WebView2 全链路或多终端 GPU 显存剖析。
